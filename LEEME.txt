SMART PARKING — PRESENTACIÓN V4.0
ESP32 + Arduino UNO | 4 sensores, 3 plazas, 6 LED, servo y pantalla LCD

PARA QUE LA CONFIGURACIÓN DE RED DESDE PYTHON FUNCIONE, ES OBLIGATORIO
CARGAR EL NUEVO FIRMWARE ESP32 V4 PRIMERO (una vez por USB).
El firmware anterior V3 solo recibe telemetría; no acepta cambio de red.
El Arduino UNO NO necesita actualizarse si ya tiene el código de 4 sensores.

1. PREPARACIÓN DEL ESP32
   Abre: ESP32/Parqueo_ESP32_WiFi_Config/Parqueo_ESP32_WiFi_Config.ino
   Cambia estas claves antes de cargar el firmware:
     AP_PASSWORD = 'CambiaEstaClave2026' (contraseña de la red de configuración)
     CONTROL_TOKEN = 'CAMBIA_ESTE_TOKEN_2026' (token para la app)
     CLAVE_OTA = 'CAMBIA_CLAVE_OTA_2026' (para futuras cargas OTA)
   No compartas las contraseñas en capturas o en un repositorio público.
   Selecciona Board 'ESP32 Dev Module' y el puerto USB de tu ESP32.
   Instala ESP32 by Espressif Systems y ESP32Servo.
   Carga por USB la primera vez; después puedes usar ArduinoOTA.
   NO copies el .ino del UNO dentro de la misma carpeta que el del ESP32.

2. CONECTAR EL ESP32 AL PUNTO DE ACCESO DE LA PRESENTACIÓN
   Activa un hotspot en un teléfono o router, preferiblemente de 2.4 GHz.
   En iPhone habilita 'Maximizar compatibilidad' si procede.
   El hotspot debe permitir comunicación entre los equipos conectados.
   Enciende ESP32 y UNO.
   El ESP32 crea su propia red: SmartParking-Setup
   Dirección de esa red: 192.168.4.1
   Conecta TEMPORALMENTE tu laptop a SmartParking-Setup usando AP_PASSWORD.
   Ejecuta ABRIR_MONITOR.cmd o SmartParkingMonitorV4.exe.
   Botón 'Usar IP de configuración' -> 'Configurar red Wi-Fi'.
   Introduce el token definido en CONTROL_TOKEN.
   Puedes pulsar 'Buscar redes Wi-Fi' (puede requerir dos pulsaciones)
   o escribir manualmente el SSID del hotspot y su contraseña.
   Pulsa 'GUARDAR Y CONECTAR HOTSPOT'.
   El ESP32 confirma que recibió las credenciales y las guarda.
   Pulsa 'Consultar estado de red' para ver si consiguió conectarse,
   su SSID y la NUEVA IP del hotspot (ej. 192.168.43.99).
   Luego conecta la laptop a ESE MISMO hotspot.
   Pulsa 'Buscar ESP32 en la red' para encontrar su IP en la subred local.
   Selecciona la IP y pulsa Conectar para monitorear.

   IMPORTANTE: credenciales recibidas NO significa conectado.
   Debes ver 'CONECTADO' e 'IP hotspot' en la consulta posterior.
   Si falla el hotspot, SmartParking-Setup sigue disponible para corregirlo.
   Evita que hotspot y AP de configuración usen ambos 192.168.4.x.
   Si el hotspot aísla clientes, la PC no podrá acceder al ESP32 por Wi-Fi.
   El ESP32 clásico no se conecta a redes exclusivamente de 5 GHz.

3. COMPROBAR INSTRUCCIONES DEL PC AL ESP32
   Dentro del monitor, botón 'Enviar instrucciones'.
   Introduce el mismo CONTROL_TOKEN y comprueba la IP.
   Selecciona 'ping' y pulsa 'ENVIAR INSTRUCCIÓN'.
   Esperado: 'Orden ACEPTADA por ESP32' + ID único coincidente.
   Probar LED verdes / LED rojos enciende los 3 pares por 2 segundos
   y luego los devuelve a los estados de las plazas.
   Puedes probar ABRIR y CERRAR la pluma SOLO con maqueta supervisada.
   El ESP32 BLOQUEA abrir si no hay cupo o falla un sensor.
   Bloquea cerrar si no confirma entrada despejada. No se fuerza cierre.
   Una confirmación HTTP demuestra orden procesada, NO movimiento físico.

4. ACTUALIZACIÓN FUTURA DEL CÓDIGO POR OTA
   El sketch ya incluye ArduinoOTA en el firmware V4.
   Después de conectar ESP32 y PC al mismo hotspot:
   Arduino IDE -> Tools -> Port -> puerto de red de parqueo-esp32,
   (si el puerto no se descubre, usa OTA por IP con herramientas ESP32).
   Subir el sketch requiere Arduino IDE y CLAVE_OTA.
   La app envía órdenes predefinidas, NO interpreta código arbitrario
   ni compila / sube archivos .ino desde su propia interfaz.
   Evita actualizar firmware durante la demostración.

5. GENERAR EXE WINDOWS
   - Instala Python 3.10+ en Windows.
   - Ejecuta CREAR_EJECUTABLE.cmd (requiere PyInstaller).
   - Se creará Escritorio/SmartParking_Presentacion_V4/SmartParkingMonitorV4.exe.
   - También puedes probar con ABRIR_MONITOR.cmd y ABRIR_DEMO.cmd.
   - El ZIP NO incluye un ejecutable Windows ya compilado.

6. SEGURIDAD Y LIMITACIONES
   - App guarda solo último host/IP, NO la clave del hotspot ni el token.
   - Credenciales viajan por HTTP sobre Wi-Fi local WPA2: usa red confiable,
     contraseña de AP única y token secreto. No indicado para uso público.
   - No hay confirmación física independiente de LED y servo.
   - Para uso real se requieren más sensores, enclavamientos y seguridad.
   - La búsqueda recorre únicamente la subred /24 conectada de la PC.
   - El AP de configuración permanece encendido, protegido por su contraseña.
   - Si el ESP32 deja de responder, primero confirma que PC y ESP32 están
     en la misma red y consulta http://IP_DEL_ESP32/api/wifi/status.

7. PRUEBAS
   PROBAR_APLICACION.cmd ejecuta 17 pruebas de interfaz anterior y 9 de red,
   realizadas con API simulada; no certifican electrónica ni Wi-Fi real.
   La versión ESP32 V4 debe compilarse en Arduino IDE con bibliotecas reales.
